# DADS PowerPointデザインスタイル手順書

この手順書は、DADSのHTML実装をPowerPointへ静的に変換するときの既定ルールである。個別のコンポーネントを再現する場合は、必ず対象のHTML、CSS、Stories、MDXを一次情報として優先する。

## 1. 作成前の確認

1. 資料の目的、対象読者、スライド構成、出力先を確認する。
2. `src/global.css`、対象コンポーネント、関連するFoundationドキュメントから使用値を抽出する。
3. 一般資料はこの手順書のテンプレート規則を使用する。コンポーネント資料は、対象実装の値がこの手順書より優先する。
4. ふるまいをPowerPoint内で疑似的に実装しない。ホバー、フォーカス、エラー、展開などは、独立した静的見本として示す。

## 2. 基本トークン

### フォント

| 用途 | 指定 |
| --- | --- |
| 本文・見出し | `Noto Sans JP` |
| 等幅表記 | `Noto Sans Mono` |
| テンプレートの本文色 | `#333333` |
| テンプレートの主見出し | `#000000` |
| 補足・フッター | `#666666` |

フォントを勝手に代替しない。環境に存在しない場合は、利用できないことを明記し、ユーザーに確認する。

### 色

一般資料の主要色は次の値を使用する。コンポーネント再現では、対象CSSの解決済みトークン値を使用する。

| 用途 | トークン | 値 |
| --- | --- | --- |
| 基調の濃紺 | `--color-key-1000` | `#00118F` |
| ブランドブルー | `--color-key-800` | `#0031D8` |
| 淡い青の文字 | `--color-key-50` | `#E8F1FE` |
| 注意のアクセント | `--color-primitive-yellow-300` | `#FFD43D` |
| 背景グレー | `--color-neutral-solid-gray-50` | `#F2F2F2` |
| 罫線グレー | `--color-neutral-solid-gray-200` | `#CCCCCC` |
| 本文 | `--color-neutral-solid-gray-800` | `#333333` |
| 白 | `--color-neutral-white` | `#FFFFFF` |
| 黒 | `--color-neutral-black` | `#000000` |

色は意味と併用する。成功・警告・エラーを色だけで区別しない。状態名、アイコン、説明テキストを必ず加える。

### フォーカス

フォーカス状態の静的見本は、HTML実装に合わせて次を使う。

- 黒の4pxアウトライン
- アウトラインから2pxのオフセット
- 外側に黄色300（`#FFD43D`）の2pxリング
- 角丸4px

## 3. スライド共通レイアウト

テンプレートは16:9（13.333 x 7.5インチ）である。ユーザー指定がなければこのサイズを使用する。

| 要素 | 既定値 |
| --- | --- |
| 左右余白 | 0.5インチ |
| セクションラベル | 8.5pt、太字、字間1.2pt、ブランドブルー |
| スライドタイトル | 27pt、太字、黒 |
| 本文 | 15pt、濃いグレー |
| カードタイトル | 14pt、太字、黒 |
| カード本文 | 10.5pt、濃いグレー |
| 補足 | 9.5pt、グレー |
| フッター | 7.5pt、グレー、字間1pt |
| フッター罫線 | グレー200、0.6pt |

テキストボックスは図形と揃えるときに余白を`0`にする。テキストが収まらない場合は、文字を縮小せず、短縮または分割する。

## 4. スライドスタイルの必須規則

### 情報設計

- 1スライドにつき結論は1つにする。タイトルは話題ではなく、読み手に伝える結論を表す。
- 本文は、結論を補強する根拠・データ・画面・コンポーネント見本だけを置く。装飾目的だけの図形やアイコンは置かない。
- 表紙、セクション区切り、クロージングは濃色背景で資料の区切りを作る。本文、比較、プロセス、表、コンポーネント見本は白背景を既定とする。
- 白背景のスライドでは、ブランドブルーを「区分・要点・操作の強調」に限定する。大面積の塗りつぶしや複数のアクセント色を同時に使わない。
- 重要な数値や結論は、本文を太字や色で過剰に装飾せず、十分なサイズ差・余白・位置で優先度を示す。

### グリッドと余白

| 項目 | 規則 |
| --- | --- |
| スライド外側 | 左右0.5インチ以上、上下も同等以上の余白を確保する |
| 基本間隔 | 0.3インチまたは0.5インチを基本単位として繰り返す |
| テキストと図形 | テキストボックスの内側余白を0にする場合も、図形との間隔は0.25インチ以上取る |
| カラム | 2カラムは左を主張、右を視覚資料とし、中央の境界を揃える |
| カード | 同じ列のカードは幅、高さ、見出し位置、本文開始位置を揃える |
| フッター | 本文領域と分離し、横罫線より下へ配置する |

コンテンツが収まらないときは、余白を削らず、文字を小さくせず、スライドを分ける。

### タイポグラフィ階層

| 階層 | 使用場面 | スタイル |
| --- | --- | --- |
| H1 | 表紙・結論・セクション | 33–35pt、太字 |
| H2 | 本文スライドのタイトル | 27pt、太字 |
| H3 | 要点見出し・カード見出し | 14pt、太字 |
| Body | 根拠・説明 | 15pt、通常 |
| Supporting | 補足・出典・キャプション | 9.5–10.5pt、通常 |
| Footer | スライド番号・資料種別 | 7.5pt、通常または太字 |

- タイトル、本文、注記の役割を同じ文字サイズやウェイトにしない。
- 本文を中央揃えにしない。中央揃えは表紙、セクション番号、短いラベルに限る。
- 日本語の長文を狭いテキストボックスへ詰め込まない。箇条書きより、短い見出しと段落または図表を優先する。

### 図表・表・UI見本

- 図表は1つの問いに答えるデータだけを表示し、単位・期間・出典を近接配置する。
- 表は比較軸を左端、数値を右寄せ、説明を左寄せにする。罫線はグレー200を使用し、塗り分けは必要な行・列だけにする。
- UI見本は実装由来の余白、色、罫線、角丸、状態を保持する。一般資料のカード表現で置き換えない。
- 画面キャプチャは切り抜き比率を変えず、枠線または淡いグレー背景で本文と区別する。
- アイコンや画像は、本文の意味を補う場合だけに使用し、説明なしの装飾画像を置かない。

### レイアウトの選択

| 内容 | 使用する標準レイアウト |
| --- | --- |
| 資料の目的・対象・作成者 | 表紙 |
| 章の開始・論点の切替 | セクション区切り |
| 結論と根拠、説明と画面・図表 | 本文と図表の2カラム |
| 同じ評価軸での3案比較 | 3カード比較 |
| 利用手順、導入手順、作業の流れ | 4ステッププロセス |
| 決定事項、担当、期限、次の行動 | クロージング |

同じレイアウトを連続して使わない。ただし、比較対象を同じ軸で反復する必要がある場合は例外とし、カードや図表の位置を固定して比較可能にする。

### 禁止事項

- タイトル下に装飾目的のアクセント線を引かない。
- グラデーション、影、角丸、色を、CSSまたはこの手順書に定義されない見た目として追加しない。
- 低コントラストの淡色文字、背景と区別できない罫線、意味を持たない小さな文字を使わない。
- 1スライドに複数の強調色、複数の見出しスタイル、複数の異なるカード形状を混在させない。
- テキストのみのスライドにしない。根拠となる図表、UI見本、プロセス、数値、または十分に構造化された比較を置く。
- ロゴ、アイコン、画面キャプチャを伸縮して縦横比を変えない。

## 5. 6つの標準レイアウト

### 表紙

- 背景は濃紺（`#00118F`）。
- 右側にブランドブルーの縦面を置き、その上に白い情報パネルを配置する。
- タイトルは左側、35pt、太字、白。
- サブタイトルと作成者情報は淡い青。
- 白パネル内にはDADS、資料種別、編集可能であることを示すラベルを置く。

### セクション区切り

- 背景はブランドブルー（`#0031D8`）。
- セクション番号、タイトル、要点を左揃えで置く。
- 右側に白い正方形と大きなセクション番号を置く。
- セクションタイトルは33pt、太字、白。

### 本文と図表の2カラム

- 左は主張と本文、右は図表・画面キャプチャ・コンポーネント見本に使う。
- 右カラムは淡いグレー背景、グレー200の0.8pt罫線。
- 本文の要点見出しは14pt、太字、ブランドブルー。
- 図表領域だけを装飾目的で埋めず、意味のある図、データ、UI見本を置く。

### 3カード比較

- 3枚のカードを同じ幅・高さ・間隔で並べる。
- カード背景はグレー50、罫線はグレー200の0.8pt。
- 各カードは同じ粒度で「要点、根拠、対象、期待効果」を書く。
- カードの高さや本文量に偏りが出る場合は、3カードを使わず2カラムまたは複数スライドに分ける。

### 4ステッププロセス

- 手順は最大4段階に整理する。
- 番号はブランドブルーの正方形に白文字で表示する。
- ステップ間はグレーの矢印で左から右へつなぐ。
- 各ステップは名称と短い説明を置き、責任者・期限などの補足は別の表か注記で扱う。

### クロージング

- 背景は濃紺。
- 左に次のアクション、責任者、期限、連絡先を配置する。
- 右に黄色300の正方形を置き、締めのメッセージを黒で表示する。
- 重要なアクションは本文ではなく、見出しと明確な担当・期限で示す。

## 6. コンポーネント資料の作成手順

1. 対象コンポーネントのHTML、CSS、Stories、JavaScript、MDXをすべて読む。
2. DOM構造、寸法、トークン、バリエーション、状態、ブレークポイント、アクセシビリティ要件を表にする。
3. 通常、ホバー、アクティブ、フォーカス、無効、エラー、選択済み、展開済みのうち実装される状態を、それぞれ独立した見本にする。
4. デスクトップとモバイルで変化する実装は、各幅を明示した別見本にする。
5. 動作や読み上げ内容は注記で説明し、PowerPointの操作として再現したように見せない。
6. 最終PPTXのレンダリングと、元のStorybookまたはHTML表示を並べて確認する。

## 7. アクセシビリティの確認

- コントラストはDADSの実装値を保持する。
- 意味を色だけで伝えない。
- 図・アイコン・画面キャプチャには内容を表す代替テキストを付ける。
- フォーカス状態は省略しない。
- 小さな注記、フッター、表のセルを判読できないサイズにしない。
- PowerPointで再現できないキーボード操作、読み上げ、アニメーションは、動作確認先を注記する。

## 8. 出力前の品質確認

1. `python -m markitdown <output.pptx>` で文字化け、順序、プレースホルダーを確認する。
2. PowerPointまたはLibreOfficeでPDFまたは画像にレンダリングする。
3. 文字切れ、重なり、余白不足、整列ずれ、低コントラスト、フッター衝突を確認する。
4. 問題を1回以上修正し、修正後を再確認する。
